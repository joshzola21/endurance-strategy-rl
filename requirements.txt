# What the hosted app installs, and nothing else.
#
# Streamlit Community Cloud reads this file, at the repository root, and runs
# `pip install -r requirements.txt` before starting the app. So this file is a
# deployment specification rather than a development one: everything in it is
# something `app/` actually imports at runtime.
#
# The development set is `requirements-dev.txt`, which adds torch,
# Stable-Baselines3, DuckDB and Jupyter. None of those is here. The app reads
# an `.onnx` export through `onnxruntime` and never opens a `.zip`, it reads
# frozen dials from `data/processed/` and never opens `laps.csv`, and it runs
# no notebook. Installing the training stack on the host would add well over a
# gigabyte to build something nothing on the page uses.
#
# Pinned to the versions in `requirements-lock.txt`, which is the environment
# every number in this project was produced on. A hosted app that quietly
# installed a different NumPy would be running a different simulator.

# The package itself, from pyproject.toml. This is what makes `import
# endurance` work on the host without the path insert in `app/__init__.py`,
# which stays as the fallback for a tree where nothing has been installed.
